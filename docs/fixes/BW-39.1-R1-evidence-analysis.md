# BW-39.1-R1 investigation and correction

Base: merged main `ddcb0369bfb0d5de51294cc8ea761b60ab534484` (PR #839).

## Demonstrated root cause, and limits of attribution

A completed Responses envelope containing an empty `output_text` convenience
aggregate and populated assistant `output_text` blocks fails in the production
Social CTA Advice route. The evidence parser chose *any string* aggregate,
including `""`, instead of assembling the valid blocks. With the identical
fictional saved Board, question, authorization and provider text, omitting the
empty aggregate returned 200 with evidence cards; including it returned 502
`evidence_response_invalid`. The new actual-route regression first failed with
`502 !== 200`, then passed after the fallback correction. Ordinary Advice already
uses a truthy aggregate fallback.

This demonstrates a parser content-loss defect. **It does not establish that the
Appics DEMO 2 incident had this envelope.** No production operational log binding
or production credentials are configured in this environment. No private Brand,
Canvas, database rows, prompts or provider response bodies were retrieved or
logged. The reported UI error alone is insufficient to attribute that incident:
all the structured rejection paths previously returned the same error. We do not
claim a verified production token exhaustion or retrospectively diagnose it.

## Production flow traced

1. Advice validates the request, signed session and independently authorized
   editable Board. Canonical Brand access is checked independently.
2. Working Canvas is validated; evidence index is bounded to 24 nodes/32,000
   serialized characters and exact 180-character quote prefixes. A 52-node
   Canvas is partial evidence coverage, not a promise to return 52 findings.
3. Social analysis captures active identity, Workspace, saved Board and native
   goal provenance even when goals are absent. Approved Learnings and canonical
   data are captured separately. Complete prompt messages are token-counted.
4. Existing model (`gpt-4o-mini` default), `store:false`, 4,096 output tokens and
   1,024 framing tokens remain unchanged. Input fitting and pre-inference scope
   revalidation remain unchanged. There is exactly one Responses request and no
   hidden repair, classifier or automatic retry.
5. Responses uses response/message `status` and `incomplete_details`, rather than
   Chat Completions `choices[].finish_reason`. Those existing completion checks
   remain. Refusal parts reject output. Ordered assistant text blocks are joined
   without inserted text; reasoning and tool data are excluded. A nonempty
   aggregate remains authoritative, even when malformed; it is never salvaged.
6. Entire JSON is parsed without clipping. Exact top-level/finding/citation keys,
   lengths, at most three findings, and one or two evidence objects remain
   required. Invalid JSON and schema failures reject the whole analysis.
7. Post-inference authorization/freshness checks now also precede invalid-output
   feedback, so a revoked/stale request gets the existing context error.
8. Server resolution still checks real saved node identity, allowed fields, exact
   indexed quotation, full-value saved/working provenance, and conservative
   absence/measurement restrictions. Unsupported citations are omitted and counted
   separately; they are not schema/parser failures. Matched quotations verify
   source text, not the AI's strategic interpretation.
9. Open in Canvas independently reauthorizes the source reference and focuses the
   exact node ID. Card expansion and opening do not run inference.

## Failure distinctions and feedback

The existing public `evidence_response_invalid` code is retained. An allowlisted
`reason` distinguishes `envelope`, `incomplete`, `refusal`, `empty`, `size`, `json`
and `schema`. The UI provides plain EN/DE feedback for incomplete, refused,
empty and unusable-format reviews, explicitly stating that no evidence cards
were produced. Manual retry remains a user action.

`AI_BRAIN_EVIDENCE_REJECTED` logs only reason, allowlisted provider status and
incomplete reason, numeric output-token usage, output character count and the
reserved output-token count. No Board/Brand/user/node identifiers, titles,
quotations, questions, prompts, arbitrary provider reason text or response bodies
enter this event. A `max_output_tokens` reason can now establish exhaustion on a
future failure; output length alone is not treated as evidence of exhaustion.
Citation mismatches retain `omittedFindings`; authorization/freshness retains the
existing 401/403/409 paths rather than being labelled invalid model output.

## Entry decision

All six focus contracts are retained. `analyze_social_ctas` is visibly named
**Review social posts**, with **Find improvement opportunities and see supporting
Canvas nodes.** Empty-state and selector guidance explain how to request Canvas
source cards. EN/DE translations are included.

Automatic deterministic routing was evaluated and not introduced. A conjunction
of Social/CTA/Canvas/evidence words cannot reliably distinguish a direct review
from quoted instructions, negation, a hypothetical example or a mixed creation
request in both languages. An exact-question allowlist would solve only that
wording and make equivalent requests behave inconsistently. Silent routing also
introduces the stricter saved-scope contract into ordinary conversation. The
explicit, labelled choice is the conservative fallback authorized by the task.

## Regression scope

The new server suite uses the exact Appics-style question, 52 fictional saved
Social nodes, signed sessions, real Advice/authorization helpers, disposable SQL,
and mocked Responses transport. It covers single/multiple findings; absent CTA
fields with positive caption evidence; missing goals; ambiguity; empty aggregate
with split blocks; ordered messages; nonempty aggregate precedence; malformed
JSON; schema mismatch; too many findings; no evidence; incomplete/refused/empty
output; quote mismatch; counterevidence; redacted logs; post-call revocation;
unchanged model/store/budget and one call. Realistic three-finding output is
asserted to fit 4,096 tokens; this does not prove every permitted response fits.

The new browser suite exercises actual Advice failure responses, unchanged mode
contracts, EN/DE labels and feedback, Light/Dark at 320/375/1440 widths, keyboard
focus, no overflow, and no automatic inference/retry. Existing BW-39.1 suites
retain forged IDs/fields/quotes, saved/working provenance, stale/revoked scopes,
exact Open in Canvas and zero inference on opening. Existing BW-26/28/36/37/38
checks and Content/Social/Campaign/Brand handoff tests are not weakened.

## Remaining limitations

The Appics incident's specific provider failure remains unattributed without
redacted operational status/usage evidence. The fix handles the demonstrated
empty-aggregate defect and makes other failures actionable; it cannot guarantee
valid model JSON. The prompt-only structured contract, three-finding ceiling,
partial evidence index, existing token allowance, and conservative semantic
filters remain. No hidden repair calls or paid retries were added. No merge or
deployment is part of this change.
