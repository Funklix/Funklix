# Feature Specs

Feature specs should define the intended behavior, dependencies, risks, and rollout plan for future product work before implementation begins.

## Example Future Specs

- `dashboard.md`
- `ai-brain.md`
- `insights.md`
- `language.md`
- `themes.md`
- `onboarding.md`

## Feature Spec Format

Future feature specs should define:

- **Purpose** — what the feature is for and the user or product problem it solves.
- **Owner** — accountable person, team, or decision owner.
- **Reads/writes** — data, state, APIs, files, or settings the feature reads from or writes to.
- **Dependencies** — product, design, engineering, data, or documentation dependencies.
- **Risks** — product, technical, UX, performance, privacy, or rollout risks.
- **Rollout plan** — implementation phases, validation plan, and release considerations.
