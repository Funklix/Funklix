# BW-33.3 Canvas-density investigation and visibility matrix

## Audited boundaries

The Canvas has one primary card renderer (`renderNode`/`updateNodeCard`) for Idea,
Campaign Variation, Content, Social Media Posting, Landing Page, Email Campaign,
Visual Concept, Image Brief, and unknown/legacy types. Post-its are rendered by
the nested `postit-template`; comments are not independent geometry nodes.
`renderNode` owns selection, inline title/content editing, drag, connector creation,
existing-node connection, compact/expand compatibility actions, and AI quick
actions. `updateNodeCard` owns role/status headers, ownership, comments, previews,
social/planning UI, images, tags and A/B variants. The stable `.node[data-id]`,
`.title`, `.content`, `.node-header-actions`, `.connector-actions`, connector
handles, comment button, action data, and nested editors remain mounted.

Geometry comes from `node.position` and the fixed 285px card width; link endpoints
are ephemeral DOM `offsetLeft/offsetTop/offsetWidth/offsetHeight` measurements.
Density changes neither state geometry nor history and requests only the established
`drawLinks` measurement pass. The Inspector is exclusively driven by selection and
`fillInspector(node)` and has no density branch. Board serialization, rehydration,
autosave, collaboration/presence, approval projection, and publishing projection
consume Board/node state; the density module is referenced only by presentation UI.

The existing Utilities popover is the display surface. The preference is global,
local, and versioned: `tendra.canvasDensity.v1` stores exactly
`{"version":1,"mode":"compact|standard|detailed"}`. Missing, malformed, null,
array, object-mode, legacy, unsupported, and read-failure values resolve to Compact.
A write failure retains the validated in-memory selection.

## Exact visibility matrix

| Role | Compact | Standard | Detailed |
|---|---|---|---|
| Idea / campaign strategy | role, title, workflow status, one critical row, required attention and connectors | Compact + two-line content preview + up to three key metadata chips | established card, content, images, tags, variants and actions |
| Campaign Variation | role, title, status, one critical row and connectors | Compact + bounded preview/metadata | established card |
| Content / supporting assets | role, title, status, one critical row and connectors | Compact + bounded content preview and metadata | established content/image/card projection |
| Landing Page | role, title, status, one critical row and connectors | Compact + bounded safe claim/CTA preview and metadata | established bounded landing preview |
| Social Media Posting | role, title, status, highest-priority warning/review/readiness/schedule/platform row and connectors | Compact + bounded caption preview and metadata | established social editor/preview and planning controls |
| Email Campaign | role, title, status, one critical row and connectors | Compact + bounded content preview and metadata | established card |
| Visual Concept / Image Brief | role, title, status, one critical row and connectors | Compact + bounded preview and metadata | established asset card |
| Unknown, placeholder, locked, system, legacy | existing role, title, status, critical row if derivable, connectors | Compact + deterministic existing-text preview | unchanged compatibility card |
| Post-its / comments | unresolved or unread attention indicator only; nested Post-it DOM retained | concise comment attention plus bounded card | established comment/Post-it behavior |

Critical-row precedence is: failure/stale/Needs Changes; review or approval action;
readiness blocker; scheduled/immediate publishing; social platform/channel; none.
Only the first matching candidate is rendered, with text and warning icon so it is
not color-only.

## Known geometry limitation

Persisted/user-resized dimensions (where legacy Board payloads provide them) remain
authoritative and are intentionally not density-adjusted. Compact reduces internal
flow and the browser-measured card height, but no density-specific dimensions are
written. A legacy explicitly tall card can therefore retain empty space rather than
risk corrupting authored geometry.
