# BW-36.21B2-R2 — Automatic deterministic diagnostics on Home

Implemented 2026-10-19 (Europe/Berlin), from `e7a933fe20ae95be2bf2f7de7c9fa79aa938ad21`, latest merged main including PR #791. Both GitHub's commit API and `git fetch origin main` confirmed the baseline. This targeted revision supersedes B2's deliberate snapshot-only Home behavior; the [B2 record](bw36-21b2-campaign-insights-and-ai-brain-home.md) and [architecture audit](../audits/bw36-21-start-screen-intelligence-and-insights-audit.md) provide the original contracts.

## Cause and shared path

Previously `homeCampaignInsights` only projected `state.insightsDiagnosticSnapshot`. A directly hydrated saved Board had no snapshot until `renderCampaignIntelligence` ran on Insights navigation. The displayed missing-snapshot message accurately described runtime state but required an unnecessary visit to Insights.

`calculateInsightsDiagnostic` now owns the existing `analyzeCampaign → captureInsightsDiagnostic → buildInsightsFindings` path and its error boundary. Explicit Insights refresh and Home use this same helper. No formulas, identifiers, ordering, severities, finding limits, provenance classifications, or applicability rules changed. The engine currently reads nodes; its edges and Brand Core parameters do not contribute diagnostic rules. The existing Canvas fingerprint includes every node field used by those rules, including `goal` and `social.cta`.

The helper writes only the ephemeral runtime snapshot. A failed calculation records an unavailable snapshot with current fingerprint and saved/live provenance, so presentation ticks do not repeatedly retry a failing context. A malformed fingerprint cannot escape the explicit Insights error boundary. Navigation and AI Brain rendering retain their existing lifecycle.

## Scheduling, freshness and authorization

Home first checks the existing loaded-Board/Brand association hydration contract, explicit `canView: true`, account/catalog identity, ready Workspace catalog, selected Workspace's authorized Board IDs, absence of a public token, and completion of loading/hydration/initial server loading. Empty Canvas returns its existing distinct state without calculation. Selected Brand preference is never an analysis source; Board A/X remains the diagnostic subject even while Brand Y is selected.

A current snapshot with matching saved/live provenance is reused, including its original analysis time. Missing/stale evidence schedules one task with `requestIdleCallback` (300 ms maximum idle wait), or a 32 ms timer fallback. Home immediately shows localized “Analyzing the current Canvas structure…” and hides obsolete findings. The existing one-second presentation observer calls the same adapter, which deduplicates pending work using account object, catalog object, account/access/Board identity, Board generation, Workspace ID/catalog generation, Canvas fingerprint and saved/live provenance. Changing context cancels/replaces pending work. Leaving Home, losing authorization or emptying Canvas cancels it.

Before calculation the task rechecks the complete captured scope, including the actual current fingerprint. A stale callback cannot analyze the replacement Board/account/Workspace. Explicit Insights refresh may supply a valid snapshot while a task is queued; it is reused. After calculation the task rechecks scope before exposing evidence and clears obsolete results. The engine runs synchronously, so ordinary browser events cannot interleave between analysis and capture. Subsequent Canvas edits invalidate evidence immediately through the same fingerprint check; observer ticks or normal Home sync schedule fresh calculation. Saving a formerly dirty Canvas triggers a new calculation rather than relabeling old live evidence as saved.

Errors remain unavailable rather than all-clear. Malformed current diagnostic contracts are also unavailable. No applicable findings and empty Canvas remain separate states. Existing View all Insights and guarded Show on Canvas adapters, evidence-key click checks, reduced-motion behavior, B1 modules and AI Brain actions are preserved.

## Performance

Analysis is deferred until after the Home navigation task, then runs the existing synchronous deterministic engine once per current context/fingerprint. It adds no worker, persistent cache, backend request or provider call. The snapshot is reused across renders and observer ticks. Each Home projection shares one freshly constructed fingerprint across its freshness checks; it does not cache by node-array identity, so in-place edits still invalidate evidence. Fingerprint/context validation remains proportional to Canvas size; there is no claim of constant-time rendering. Home's preview now indexes eligible/unique node IDs once instead of nesting node scans for every affected ID, preserving duplicate-ID rejection and the original applicability semantics.

A 20,000-node browser regression measures initial navigation/render, engine time and five repeated renders; it asserts that analysis has not run during initial rendering, that only one task is queued, that existing snapshots are reused, and that automatic findings exactly match the original engine. Timing ceilings are generous regression guards, not device-independent latency promises. The unchanged synchronous engine can still consume a browser task on exceptionally large Boards; deferral keeps it off the initial navigation task.
