# BW-32.2 LinkedIn connection

## Server environment

Configure `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, and the exact absolute HTTPS
`LINKEDIN_REDIRECT_URI`. Set `LINKEDIN_SHARE_ON_LINKEDIN=true` only after the app has
the Share on LinkedIn product. Configure `SOCIAL_CONNECTOR_ENCRYPTION_KEY_VERSION`
and the corresponding `SOCIAL_CONNECTOR_ENCRYPTION_KEY_V<n>` with a base64-encoded
32-byte random key. There are no defaults. These variables are server-only.

The server requests `openid profile`, plus `w_member_social` only when Share on
LinkedIn is explicitly enabled. Capability is based on the scope string actually
returned by the token endpoint; requesting a scope never grants it.

## Official contract evidence (accessed 2026-09-03)

* [Authorization Code Flow](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow) defines `https://www.linkedin.com/oauth/v2/authorization`, `https://www.linkedin.com/oauth/v2/accessToken`, exact registered redirect matching, state validation, 30-minute authorization codes, and commonly 60-day access tokens. Actual `expires_in` is authoritative.
* [OpenID Connect](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2) defines `openid profile`, the `https://api.linkedin.com/v2/userinfo` endpoint, and the app-specific `sub`, `name`, and optional `picture` claims used here. Email is neither requested nor stored.
* [Share on LinkedIn](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin) documents that the product provides `w_member_social`. Access shown in an application's Auth tab remains authoritative.
* [Programmatic refresh tokens](https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens) are restricted to approved partners. The connector accepts their absence and stores one only if returned.
* [API versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning) applies LinkedIn-Version headers to versioned Marketing APIs. This phase calls only OAuth and OIDC UserInfo, so it sends no invented version header.
* [Token revocation](https://learn.microsoft.com/en-us/linkedin/shared/authentication/revoking-an-access-token) describes member-side revocation rather than a generally available server revocation endpoint. Disconnect therefore fails safe by revoking local encrypted credentials and disabling the destination.
* [Rate limits](https://learn.microsoft.com/en-us/linkedin/shared/api-guide/concepts/rate-limits) says limits vary by endpoint/app/member and are visible in the Developer Portal. The connector makes only deliberate bounded calls and does not guess quotas.

No publishing operation or endpoint is implemented in this phase.

## Manual production verification

1. Create or select a LinkedIn Developer application.
2. Add the official Share on LinkedIn product.
3. Confirm the exact scopes available in the application's Auth tab.
4. Register the exact Funklix HTTPS callback URL.
5. Configure the client ID, client secret, redirect URI, and vault key in Vercel.
6. Deploy.
7. Connect a controlled LinkedIn account and inspect the consent screen.
8. Return to Settings and confirm identity, Personal profile, granted publishing permission, expiry, and health.
9. Disconnect and confirm the credential is unusable locally.
10. Reconnect and confirm a new OAuth attempt and credential lifecycle.

This checklist is required before claiming a live LinkedIn connection succeeded.
