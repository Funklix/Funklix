# Founder Story Module F1 — Specialized Editor Shell and Manual Structured Fields Audit

## Summary

Founder Story F1 adds a narrowly scoped specialized editor branch for typed Founder Story Custom Tiles inside the existing Brand Core sticky editor shell. The runtime change keeps Founder Story as a Custom Tile, preserves the existing stable tile ID, `moduleType`, title, content, items, references, selection key, section routing, deletion behavior, and board-scoped persistence path, and adds only manual structured source fields under `moduleData.founderStory` when the user edits those fields.

No AI generation, API changes, card redesign, completion status, registry metadata, or migration behavior are included in F1.

## Dependency Findings

- Phase 5A persists `moduleType` when canonical Missing Knowledge tiles are created, so newly created Founder Story tiles can be identified by `moduleType: "founder_story"`.
- Phase 5B keeps runtime adapter behavior read-only and already prefers valid persisted `moduleType` for module identity.
- Phase 5C create/select duplicate prevention prefers valid persisted `moduleType` before legacy title fallback.
- Phase 5D visible presence detection treats valid persisted canonical `moduleType` as authoritative before legacy exact-title fallback.
- F0 section routing now keeps typed canonical tiles in their registry-defined sections even after title edits.
- The registry already defines Founder Story as a canonical Missing Knowledge module; F1 does not require new registry capabilities.
- Existing app.js helper `getValidPersistedMissingKnowledgeModuleDefinition(tile)` is sufficient to validate the specialized-editor discriminator.

## Existing Selection Flow

Custom Tile cards are rendered with runtime keys generated by `getCustomTileRuntimeKey(tile, index)`, preferring `custom-id:<id>` for stable `km_` IDs and falling back to `custom:<index>` for legacy tiles without stable IDs. Selecting a card stores that key in `state.brandCoreSelectedKey` and calls the existing Brand Core render/editor refresh path.

The editor resolves the selected Custom Tile through `getCustomTileByRuntimeKey(activeKey)`, which delegates to `findCustomTileIndexByRuntimeKey(activeKey)` and returns the source tile object and index from `state.brandCore.customTiles`.

## Existing Editor Render Flow

`renderBrandCoreEditor()` is the sticky editor renderer. Before F1, every valid Custom Tile used the same generic editor branch with:

- `bc-custom-title` for the editable title input.
- `bc-custom-content` for the editable content textarea.
- `bc-custom-delete` for deletion.

Editor markup is regenerated whenever the selected key changes or the editor is rerendered. Event listeners are attached to the freshly rendered elements each time, so listener lifetime is tied to the current editor DOM.

## Existing Save and Autosave Behavior

The current generic Custom Tile editor saves on input. Title input mutates `tile.title`, content textarea mutates `tile.content`, and both call `saveBrandBrainState()` immediately. There is no independent Custom Tile debounce scheduler in the sticky editor branch.

F1 preserves that behavior for typed Founder Story fields: editing a structured field writes the additive `moduleData.founderStory` shape and calls `saveBrandBrainState()` through the same immediate-save semantics. Editing the narrative writes `tile.content` and calls `saveBrandBrainState()`.

## Existing Deletion Behavior

The existing Custom Tile delete control removes the tile at its resolved index from `state.brandCore.customTiles`, resets selection to `brandCore`, saves state, rerenders cards, and rerenders the editor. F1 extracts this sequence into a small shared helper so the generic and Founder Story specialized editors use the same deletion behavior.

## Specialized Editor Discriminator

F1 renders the specialized editor only when the selected tile has a valid persisted canonical Founder Story type:

```js
getValidPersistedMissingKnowledgeModuleDefinition(tile)?.id === "founder_story"
```

This means title alone never activates the specialized editor. Legacy untyped tiles titled `Founder Story`, manual untyped tiles renamed `Founder Story`, invalid typed tiles titled `Founder Story`, and other typed modules continue to use the generic Custom Tile editor.

## Founder Story Stored Shape

F1 stores manual structured source fields additively under:

```js
moduleData: {
  founderStory: {
    founderNameRole: "",
    background: "",
    observedProblem: "",
    motivation: "",
    turningPoint: "",
    proofPoints: "",
    vision: ""
  }
}
```

The editable narrative remains `tile.content`. F1 does not use `items` for Founder Story storage, does not add schema versioning, and does not persist derived completion status.

## Field Contract

| Field | Storage key | Required? | User editable? | Notes |
|---|---|---:|---:|---|
| Founder name and role | `founderNameRole` | No | Yes | Captures the person and role in one v1 field. |
| Background and professional context | `background` | No | Yes | Source material for credibility and origin. |
| Problem or insight personally observed | `observedProblem` | No | Yes | Captures the founder's direct problem insight. |
| Personal motivation | `motivation` | No | Yes | Captures why the founder cared. |
| Turning point | `turningPoint` | No | Yes | Captures the moment that caused action. |
| Proof points and credibility | `proofPoints` | No | Yes | Kept as a string in F1, not an array. |
| Vision and future impact | `vision` | No | Yes | Captures long-term ambition and impact. |
| Founder Story Narrative | `content` | No | Yes | Existing Custom Tile content remains the narrative. |

All fields are optional. Partial saves are valid.

## Legacy and Empty Data Handling

F1 adds read-only display normalization through `getFounderStoryModuleData(tile)`. It returns empty-string defaults for all seven fields when:

- `moduleData` is absent.
- `moduleData` is `null`.
- `moduleData.founderStory` is absent.
- `moduleData.founderStory` is `null`.
- `moduleData.founderStory` is malformed.
- Individual structured values are missing or non-string.

Opening the editor does not create `moduleData`, does not create `founderStory`, and does not trigger save. The nested structure is persisted only after user input in a Founder Story field.

## Editor UX

The specialized editor remains inside the existing sticky Brand Core editor shell. It includes:

- A canonical module label: `Founder Story Knowledge Module`.
- The existing editable title behavior, using a Founder Story-specific title input.
- Brief explanatory helper copy.
- Seven single-column structured source textareas.
- A `Founder Story Narrative` textarea backed by `tile.content`.
- The existing removal action semantics.

F1 intentionally does not add tabs, accordions, wizard steps, a modal, a full-page route, AI controls, progress badges, version history, previews, or regenerate controls.

## DOM IDs Added

The new Founder Story editor uses unique IDs with the `brand-core-founder-story-` prefix:

- `brand-core-founder-story-title`
- `brand-core-founder-story-founder-name-role`
- `brand-core-founder-story-background`
- `brand-core-founder-story-observed-problem`
- `brand-core-founder-story-motivation`
- `brand-core-founder-story-turning-point`
- `brand-core-founder-story-proof-points`
- `brand-core-founder-story-vision`
- `brand-core-founder-story-narrative`
- `brand-core-founder-story-delete`

Repository search confirmed this prefix was not present before implementation, so the new IDs do not collide with existing generic editor IDs.

## Event Listener Strategy

Listeners are bound to elements inside the newly rendered editor markup, matching the existing editor lifecycle. No global listeners are added. Because `renderBrandCoreEditor()` replaces `el.brandEditorPanel.innerHTML` on selection/rerender, old element-bound listeners are discarded with their DOM nodes and cannot accumulate across renders.

## Save Merge Strategy

Structured field input uses an additive merge:

- Preserve all existing `tile` properties.
- Preserve `tile.id`.
- Preserve `tile.moduleType`.
- Preserve `tile.items`.
- Preserve `tile.references`.
- Preserve unrelated tile metadata.
- Preserve unrelated `moduleData` keys.
- Preserve existing `moduleData.founderStory` keys not in the seven-field F1 contract.
- Write the seven F1 fields as strings.

Narrative input continues to write only `tile.content`.

## Generic Editor Preservation

The generic Custom Tile editor remains active for:

- Untyped manual Custom Tiles.
- Typed modules other than `founder_story`.
- Legacy untyped tiles titled `Founder Story`.
- Invalid `moduleType` tiles titled `Founder Story`.
- Manual tiles renamed to canonical labels.

Generic title/content/delete DOM IDs remain unchanged.

## No Open-Time Mutation Confirmation

The specialized editor's render path reads normalized field values for display, sets editor HTML, and attaches local listeners. It does not mutate the source tile until a user edits a field or the narrative/title inputs. Opening a typed Founder Story tile with content-only or malformed `moduleData` therefore does not create nested data or trigger persistence.

## Persistence Confirmation

The existing Brand Core snapshot path serializes `state.brandCore` with plain JSON cloning, and `normalizeBrandCoreState()` preserves unknown Custom Tile fields by retaining `customTiles` entries instead of reconstructing each tile from a strict schema. Therefore additive `moduleData.founderStory` survives the existing save/load flow without API or persistence schema changes.

## Runtime Confirmation

F1 is limited to `app.js` runtime behavior and adds no API, registry, adapter, identity, campaign, HTML, workflow, or script changes. It preserves Phase 5 identity, F0 section routing, card rendering, selection keys, deletion semantics, and existing Custom Tile persistence.

## Risks

| Risk | Mitigation |
|---|---|
| Generic editor overwrite of specialized fields | Founder Story uses a specialized branch and additive merge for `moduleData`. |
| Open-time mutation | Display normalization returns a detached object of strings and does not write to the source tile. |
| Unknown nested fields dropped | Merge preserves unrelated `moduleData` keys and unrelated founderStory keys. |
| Duplicate listeners | Listeners bind only to newly rendered editor elements. |
| DOM ID collision | New IDs use a unique `brand-core-founder-story-` prefix checked by repository search. |
| Title-only specialization | Discriminator uses validated persisted `moduleType`, not title. |
| Legacy data loss | Legacy untyped Founder Story-title tiles remain generic and are not migrated. |
| Broad app.js edits | F1 changes only the Custom Tile editor dispatch and a small helper cluster. |
| AI scope creep | No AI controls, API calls, prompt logic, or generation behavior are added. |

## Rollback

Rollback can remove the Founder Story helper cluster, remove the specialized branch in `renderBrandCoreEditor()`, and restore the generic Custom Tile delete handler body if desired. Existing saved `moduleData.founderStory` fields are additive and ignored by the pre-F1 generic editor, so rollback does not require migration.
