# BW-19 private/public Board sharing audit

## Pre-implementation findings and smallest safe contract

The runtime creates `boards` idempotently in `_boards-storage.js` and adds compatibility columns with `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`; creation is centralized in `POST /api/boards`. BW-18 stores Board invitations in `board_editors` (`editor` or `viewer`) and resolves owner, invited role, authenticated legacy-unowned claim access, unrelated authenticated access, and anonymous access in `_board-access.js`. Capabilities are authoritative server output, not authorization input. `_board-serializer.js` is the centralized item serializer. Before BW-19, owner/editor/unowned received full Board data, Viewer received a redacted read-only shape, while both unrelated authenticated users (`non_owner`) and anonymous UUID visitors (`anonymous_shared`) also received that redacted Canvas. Legacy unowned Boards remained claimable by any authenticated user.

The normal Board loader and passive refresh directly GET `/api/boards/:id`; Board creation, duplication, conflict-copy, and save-as-new all use the collection POST. Routing resolves `/boards/:uuid` from `location.pathname`, uses `history.pushState` after creation, and refreshes that path. The previous boot reset Board Brand state, fetched the Board, hydrated Canvas and local Canvas storage, then started autosave, polling, and presence. Failure showed a Board-load error but could leave prior Canvas state. Presence independently authorizes through BW-18 access and exposes identities only for owner/editor/viewer/unowned. The Board list is authenticated and returns only owned, invited, or legacy-unowned Boards; Viewer list rows are redacted. The Copy Link toolbar action copied the UUID URL and opened the lifecycle-safe permissions popover whose single capture-phase outside listener is centrally removed. Nested routes use Vercel filesystem routing under `api/boards/[id]/...`. Session verification already demonstrates fixed-buffer `crypto.timingSafeEqual`; no prior Board-share token helper existed. Coverage was concentrated in BW-18 access/redaction and popover lifecycle checks plus Board/Brand, document, provenance, recovery, and Canonical regression scripts.

The confirmed minimum contract is one active link per Board: 32 random bytes encoded as canonical unpadded Base64URL (43 characters), SHA-256 stored as 64 lowercase hex characters, fragment URL `/boards/<uuid>#public=<token>`, and the dedicated `X-Board-Public-Token` header on Board item GET only. An authenticated owner/editor/viewer/unowned role always wins before token evaluation. Otherwise, valid token verification yields only `public_viewer`. All missing, malformed, disabled, wrong, rotated, or revoked cases return the same 404.

## Transition and schema

The additive columns are `public_view_enabled BOOLEAN NOT NULL DEFAULT FALSE`, `public_view_token_hash TEXT NULL`, and `public_view_token_created_at TIMESTAMPTZ NULL`, with a state constraint requiring all metadata to be null when disabled and a canonical hash plus timestamp when enabled. Existing and new Boards are private immediately. There is no backfill, generated token, table recreation, Canvas deletion, or membership change. Thus old anonymous UUID-only links stop exposing content; normal signed-in owner/editor/viewer links and authenticated legacy-unowned claim behavior remain. Owners must explicitly create a replacement public link.

Sharing status/create-or-rotate/delete live at `/api/boards/:id/sharing` and require authoritative Board ownership. Writes update only sharing columns, deliberately avoiding `updated_at` so Canvas optimistic concurrency is independent. POST accepts exactly `{ "operation": "create_public_view_link" }`; its successful response is the token's only server disclosure. DELETE atomically clears all sharing metadata.

Public responses contain Board id/name, sanitized Canvas, safe Board timestamps, `public_viewer` capabilities, and `brand_visibility: "hidden"`. They omit Brand association/Core, provenance/recovery, ownership/creator, membership, sharing metadata, and presence. Unauthorized loads clear Canvas, protected Brand state, association, and presence before showing the neutral private/link-invalid message. The fragment stays in browser navigation, is held only in memory, is sent only on Board item GET, is never persisted, and is never sent to presence. Owner-generated raw tokens live only in the open popover and are invalidated by its lifecycle/generation guards.

No Brand-level or Workspace-level role is introduced.
