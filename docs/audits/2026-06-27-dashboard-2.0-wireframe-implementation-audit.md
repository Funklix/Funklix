## Why this spec is needed

- The Dashboard is Mission Control, not a homepage or board list.
- Current product documents establish that Dashboard orchestrates and owns no canonical knowledge.
- Dashboard 2.0 needs a clear information architecture before implementation so it does not duplicate Boards, AI Brain, Insights, Campaign Canvas, tasks, or analytics.
- The future implementation needs conservative MVP/later boundaries because several desired sections depend on data ownership, analytics, collaboration, AI Brain 2.0, assigned Nodes, or deployment models that may not exist yet.

## Why no runtime work was performed

No runtime work was performed because this task is product and implementation planning only. Implementing UI, CSS, data reads, analytics, AI suggestions, task models, or routing before the spec would violate scope discipline and risk creating incorrect data ownership.

This audit and spec do not modify:

- `app.js`
- `index.html`
- `styles.css`
- API files
- Campaign Canvas
- Campaign V3
- Routing
- Save/load
- Auth/session
- Existing Dashboard behavior

## Key audit decisions

- Dashboard 2.0 should answer: “What deserves my attention today?”
- Dashboard owns no canonical knowledge.
- Dashboard reads and orchestrates.
- Dashboard should not become Boards, AI Brain, Insights, a task database, or an analytics surface.
- “Tasks are assigned Nodes” is the safest initial product model for Today's Focus.
- Live Campaigns should be hidden or deferred until real deployed/running campaign data exists.
- Suggested Opportunities should start as safe placeholders until AI Brain 2.0 integration is audited.
- Brand Avatar copy should be collaborative, first-person where appropriate, and never nagging or generic.

## How future implementation should reference the spec

Future Dashboard implementation PRs should cite `docs/product/dashboard-2.0-implementation-spec.md` when deciding:

- which sections to build,
- what each section reads from,
- whether the section may write anything,
- what MVP data is safe,
- what must wait for APIs, analytics, AI Brain 2.0, collaboration, tasks, deployments, or integrations,
- how Brand Avatar language should sound,
- whether Dashboard is accidentally becoming storage.

## Recommended next implementation PR

The next implementation PR should be Dashboard 2.0 static layout / visual structure only, using existing design components and safe placeholders.

It should not include business logic, analytics, real AI suggestions, assigned-node task queries, live campaign metrics, new APIs, new storage, or writes to any owning object.

## Decision

Create `docs/product/dashboard-2.0-implementation-spec.md` and keep this change documentation-only.
