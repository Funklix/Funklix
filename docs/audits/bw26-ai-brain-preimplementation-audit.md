# BW-26 — AI Brain V1 pre-implementation audit

**Baseline:** `c87f950`, including merged BW-25.1. **Scope selected:** one authenticated, read-only advice endpoint and replacement of the existing Brain panel; no persistence, mutation, funnel simulation, schema, or dependency changes.

## Findings completed before implementation

1. **DOM and behavior.** `index.html` exposes `ai-brain-nav-btn`, `ai-brain-view`, and `ai-brain-summary`. `app.js` maps all three, navigation selects `ai_brain`, and `renderCampaignIntelligence()` previously replaced the summary with a static avatar-less Brain header, refresh action, heuristic score, suggestions, create-node handlers, and inert quick actions.
2. **Insights overlap.** Brain and Insights both consumed the browser-only `analyzeCampaign()`. BW-25 separated Insights presentation but deliberately retained Brain's duplicate score and authoring suggestions. The advisor replacement can leave Insights and its deterministic snapshot unchanged.
3. **Model conventions.** Text routes use OpenAI Responses with `OPENAI_API_KEY`, normally `gpt-4o-mini`, JSON or text extraction, and JSON HTTP handlers. Some specialized routes expose model environment variables. Older routes leak provider bodies; newer retrieval code demonstrates `AbortController` timeouts. BW-26 should use a feature-specific model variable, a bounded timeout, and neutral errors.
4. **Board and Brand authorization.** `_auth-session.js` verifies the signed session cookie. `_board-access.js#getBoardAccess` is the authoritative Board resolver; `_brand-access.js#getBrandAccess` independently resolves Canonical Brand membership.
5. **Capability derivation.** Board owner, explicit Board editor/viewer, legacy authenticated unowned claimant, and associated Brand owner/admin/editor/viewer resolve in `getBoardAccess()`. `accessForRole()` grants `canEdit` only to owner/editor/unowned and Brand owner/admin/editor. Public, unrelated, anonymous, Board viewer, and Brand viewer do not receive it.
6. **Canvas representations.** Saved Canvas is `boards.canvas_json`; current working Canvas is browser `state.nodes`/`state.edges`, serialized by `serializeState()`. `state.isDirty` identifies unsaved working changes, while Board save uses a last-known update timestamp and save request generations.
7. **Selection and Inspector.** `state.selectedPrimary` is the single focal node id; `getNode()` resolves it. Inspector context additionally derives parent, child, and sibling nodes from current edges.
8. **Brand boundaries.** The Board snapshot is `boards.brand_core_snapshot` and is disclosed by Board routes according to Board capability. Canonical `brands.brand_core` requires an independent `getBrandAccess()` result. Board-editor status alone does not grant Canonical Brand access.
9. **Language.** `uiLanguage` translates interface chrome; `campaignLanguage` controls generated campaign artifacts. Conversational Brain output is interface communication, so V1 explicitly requests `uiLanguage` (`en`/`de`) without changing campaign-generation language.
10. **Lifecycle.** Existing robust flows use `AbortController`, incrementing request ids, account/Board identity, Board load generations, and stale-response checks. Brain should copy those patterns and additionally bind a response to selection, language, nodes, and edges.
11. **Legacy dependencies.** BW-25 regression coverage requires the three legacy DOM ids and previously required `renderCampaignIntelligence()` to retain creation behavior. BW-26 preserves the ids but intentionally supersedes its assertion about Brain mutation with a separate-render assertion.
12. **Boot and integrity.** `scripts/check-browser-script-integrity.js` parses all local classic browser scripts. Runtime Boot Safety also has the repository-wide `report-change-scope` and focused regression-script convention; BW-26 needs a dedicated boundary check and must keep `app.js` parseable without new browser dependencies.

## Smallest safe implementation decision

The endpoint must accept only Board id, question, selected-node id, working nodes/edges, and response language. It must load the Board snapshot itself, independently attempt Canonical access, recompute deterministic diagnostics server-side, authorize `canEdit` before any model call, cap and sanitize working context, time out provider work, and return only advice plus a context manifest. The browser needs an ephemeral transcript, explicit saved/unsaved and selected-node disclosure, neutral viewer state, and abort/stale rejection. It needs no write control, proposal/apply path, chat storage, analytics claim, or simulation.
